# intent_MILEAGE — проверка пробега в расчёте решения по заявке

Дата: 2026-10-08. Задача MILEAGE. Собрано после интервью Grill Me —
лог: `docs/intent/grill_MILEAGE.md`.

## Замысел

Добавить в расчёт решения по заявке проверку пробега авто: пробег не
больше 400 000 км, иначе решение `review` (исходная формулировка задачи
из интервью). Пробег становится вторым входом расчёта решения наряду с
LTV.

## Зачем

Не зафиксировано: бизнес-обоснование правила в интервью не прозвучало —
вынесено в Open questions.

## Constraints

1. Порог 400 000 км — включительно: ровно 400 000 км остаётся в
   `approve`-зоне при низком LTV; в `review` переводит только пробег от
   400 001 км — «ответ в интервью», вопрос 3.
2. Пробег не перекрывает жёсткий вердикт по LTV: при LTV-вердикте
   `reject` решение остаётся `reject`, даже если пробег > 400 000 км;
   пробег только не даёт `approve` — «ответ в интервью», вопрос 1.
3. Матрица решений: LTV < 60 + пробег ≤ 400 000 → `approve`; LTV < 60 +
   пробег > 400 000 → `review`; LTV 60–85 → `review` независимо от
   пробега; LTV > 85 → `reject` независимо от пробега — «ответ в
   интервью», вопрос 4; границы LTV 60 и 85 — код:
   `backend/config/rules.php`.
4. Неуказанный пробег — ошибка валидации: отсутствующий ключ, `null` и
   пустая строка трактуются одинаково как неуказанный пробег; значение 0
   допустимо только при явной передаче — «ответ в интервью», вопрос 2.
   Текущее поведение (пустая строка нормализуется в 0 и проходит
   валидацию) — код: `backend/src/Domain/ApplicationValidator.php`.
5. Граница валидации пробега 500 000 км не меняется: пробег выше —
   ошибка валидации, до решения заявка не доходит; новое правило
   срабатывает только в валидном диапазоне 400 001–500 000 км —
   «ответ в интервью», вопрос 5; число 500 000 — код:
   `backend/config/rules.php`.
6. При `review` и `reject` одобренный лимит — 0; состав полей ответа не
   меняется — «ответ в интервью», вопрос 6; текущее поведение лимита —
   код: `backend/src/Domain/AssessmentService.php`.
